# V1.2 RAW OCIO Release Gate

## Scope

V1.2 is ready only when RAW import, decode provenance, OCIO transform execution, analysis trust, UI diagnostics, and packaged runtime dependencies all pass together.

## Runtime Dependencies

- FFmpeg: packaged as a Tauri sidecar through `src-tauri/tauri.conf.json`.
- FFprobe: packaged as a Tauri sidecar through `src-tauri/tauri.conf.json`.
- BRAW bridge: packaged as a Tauri sidecar through `src-tauri/tauri.conf.json`.
- REDline: packaged as a Tauri sidecar through `src-tauri/tauri.conf.json`.
- OCIO config: discovered from `OCIO`, then bundled resources at `ocio/config.ocio`, `aces/config.ocio`, or `config.ocio`.
- OCIO processor: discovered from `CINEFLOW_OCIO_PROCESSOR`, then bundled resources at `bin/ocioconvert`.
- LibRaw bridge: discovered from `CINEFLOW_LIBRAW_BRIDGE`.

Do not add an `externalBin` entry for a binary that is not present in `src-tauri/bin`; Tauri packaging should fail loudly only after the binary is intentionally bundled.

## Startup Diagnostics

The app info surface must report:

- FFmpeg path and version.
- FFprobe path and version.
- BRAW bridge path and active state.
- OCIO config status and source.
- OCIO processor status and active state.
- LibRaw bridge decode status and active state.

## Release Checklist

- [x] Import picker accepts video, BRAW, vendor RAW, open camera RAW, and proxy-guided RAW extensions.
- [x] Each imported source receives a decode path label.
- [x] Open RAW remains provisional unless LibRaw frame decode is available.
- [x] Vendor/proprietary RAW remains behind vendor decode or operator proxy unless a legal decoder is available.
- [x] OCIO config and processor status are shown separately in Camera Match Lab.
- [x] Analysis metrics become trusted only after direct decode and successful OCIO frame transform.
- [x] Proxy analysis remains explicit and provisional unless product policy changes.
- [x] App info reports FFmpeg, FFprobe, BRAW, OCIO, and LibRaw diagnostics.
- [ ] macOS installer package passes. The release binary builds, but DMG bundling currently fails in `bundle_dmg.sh`.
- [ ] Windows build passes with sidecar binaries present and signed as required. Current sidecar check is missing `ffmpeg-x86_64-pc-windows-msvc.exe` and `ffprobe-x86_64-pc-windows-msvc.exe`.
- [ ] Runtime ACES/OCIO assets are bundled or configured. Current package has no bundled `ocio/config.ocio`, `aces/config.ocio`, `config.ocio`, or `bin/ocioconvert`.
- [ ] LibRaw frame-decode bridge is bundled or configured. Current package has no `CINEFLOW_LIBRAW_BRIDGE` target or bundled LibRaw bridge binary.
- [ ] Astro docs are updated only after manual production approval.

## Current Gate Status

As of this roadmap update, V1.2 is not release-approved. The application-side RAW/OCIO behavior gates are implemented and verified, but package/runtime gates remain open: macOS DMG bundling, Windows FFmpeg/FFprobe sidecars, OCIO config/processor assets, LibRaw frame decode bridge, and Astro production approval.

## Validation Evidence

- `cargo test --manifest-path src-tauri/Cargo.toml` passes with 76 Rust tests.
- `npm run build` passes for the frontend production bundle.
- `npm run build:direct` builds the macOS release application binary at `src-tauri/target/release/cineflow-suite`, then fails during DMG bundling in `bundle_dmg.sh`.
- `node scripts/production/verify_windows_sidecars.mjs` fails because `src-tauri/bin` does not contain Windows `ffmpeg` or `ffprobe` sidecars.
- `src-tauri/resources` currently contains camera/look presets only; no bundled OCIO/ACES config is present.
- `src-tauri/bin` currently contains FFmpeg/FFprobe, BRAW bridge, and REDline sidecars, but no `ocioconvert` or LibRaw bridge.

## Phase Update: Runtime Readiness Check

The app now exposes a V1.2 RAW / OCIO readiness report in Settings. It separates implemented behavior from runtime blockers:

- OCIO config and OCIO processor are evaluated separately.
- LibRaw frame decode is required before open camera RAW can become direct/trusted analysis.
- Windows packaging and Astro documentation remain manual approval gates.
- The report stays blocked until all runtime and manual gates pass.
